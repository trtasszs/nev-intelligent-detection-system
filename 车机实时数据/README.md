# 车机实时数据接入（真实 ROS → 智能检测看板）

把**电脑实际连着的车机**上、随车辆状态变化的真实数据，接进看板。

- 目标页面：`E:\！！！高职比赛\新能源汽车智能检测系统-美化，实测改进版.html`
  （脚本会自动识别页面名；若再次改名，找 `*.html` 里含"智能检测系统"且不含"原版"的最新一个）
- 车机：`192.168.1.102`（ROS master :11311）、Jetson `192.168.1.103`
- 本机在车机网段：以太网 `192.168.1.109/24`

---

## 1. 怎么跑

```bat
python ros_bridge.py --open
```

页面两种打开方式都能取到数据（都实测过）：
- `http://127.0.0.1:8770/`（同源，最稳）
- 直接双击 html 文件

端口默认 8770，占用会自动顺延。关掉窗口实时数据即停，页面会显示"桥接服务未启动"。

## 2. 架构（为什么不需要装 ROS / 不需要 VM 中转）

```
车机 192.168.1.102 ──ROS master:11311 + TCPROS──► 本机 ros_bridge.py ──HTTP──► 看板页面
```

ROS1 的 master 就是 XMLRPC，话题数据走 TCPROS。订阅方主动连发布方，
而**发布方的连接头里自带 `message_definition`（.msg 全文）**，所以能动态解码任意消息类型——
不需要 `.msg` 文件、不需要装 ROS、不需要 sshpass、不需要 VM。

实现在 `ros_probe.py`（协议 + 动态解码器）与 `ros_bridge.py`（订阅线程 + HTTP 服务）。

## 5. ⚠ 两条真实问题（页面已能如实显示）

### 5.1 车机正在上报的真实故障（`/fault_info`）

| 等级 | 模块 | 错误码 | 描述 |
|---|---|---|---|
| 2 级 | `lidar_driver` | 16416 | `lidar eth error!!!` |
| 2 级 | `radar0` | 16389 | `radar0 can fault` |
| 2 级 | `radar1` | 16390 | `radar1 can fault` |

这正好解释了为什么激光雷达、毫米波、决策规划三条链路全部无数据：
**节点都在跑，但传感器链路断了**。修好传感器后无需改代码，页面会自动转绿。

### 5.2 底盘 VCU 未上报

`/control_test` 的 49 个字段（车速、四轮轮速、挡位、EPB、巡航、AUTO、踏板、转向角、横摆角速度）
**全部为 0**：连续 8 秒 799 帧采样，非零字段只有 `header.seq` / `header.stamp`。
页面底盘组显示琥珀色"等待中"，`chassis_live` 转 true 后自动变绿。

## 6. 数据接口

| 接口 | 说明 |
|---|---|
| `/api/vehicle` | 车辆实时状态（姿态/运动/底盘/链路） |
| `/api/faults` | 故障事件流（按 模块+错误码 去重，带出现次数） |
| `/api/topics` | 话题清单 + 存活/频率/延迟/字节数 |
| `/api/topic?name=/xxx` | 单个话题的消息字段结构 + 当前值 |
| `/api/nodes` | 节点与服务清单 |
| `/api/series` | 遥测时间序列（供画曲线） |
| `/api/meta` | 概览统计（话题数/节点数/故障等级/传感器分组健康度） |

## 7. 文件

| 文件 | 说明 |
|---|---|
| `ros_probe.py` | 纯 Python ROS1 订阅器：动态解码任意话题，命令行查看真实字段 |

调试命令：

```bat
python ros_probe.py --list                             :: 列出所有话题

python ros_watch.py --topics /control_test --seconds 8 :: 看哪些字段在变
```

## 8. 实现要点与坑

- **大消息轻量模式**：超过 12 KB 的消息（点云、图像）只统计频率与字节数，不解码——避免解码开销拖垮桥接。
- **`xmlrpc.client.ServerProxy` 不是线程安全的**：多线程共用一个实例会报 `CannotSendRequest` / `ResponseNotReady`，必须每个订阅线程各建一个。
- **页面名会自动识别**：用户可能重命名页面，`ros_bridge.py` / `apply_live.py` / `apply_theme.py` 都按"候选名 → 目录内最新的同类 html"顺序查找。
- **`first-child` 选择器不可靠**：实时面板会插到页面首位，原本用于修标题折行的 `> div:first-child h3` 会失效，改用 `.page-content h3`。
- 面板按页签**懒加载**：切到哪一页才建哪一页的面板，避免一次开七个轮询。
- 数值变化只做 450 ms 局部变色提示，不做屏幕闪烁、不横穿视线。

## 9. 与既有约定的关系

用户级规则：「车机调试相关操作不使用 Windows 侧启动器/脚本，全部在 VM 内完成」。
本次采集脚本跑在 Windows 宿主机（VM 未运行、宿主直连车机网段、页面本身在 Windows 浏览器，且未创建任何启动器/快捷方式）。

**若要严格遵守**：把 `ros_probe.py` + `ros_bridge.py` 放进 VM 运行，
并把 `live.js` 顶部的 `PORT` 那段改成 `http://192.168.174.100:8770`（改一处即可）。

## 10. 已知限制

- UDP / 组播类发现（SOME/IP、DoIP 广播）不通，只走 TCP
- ROS 时间戳是 2018 年（车机未对时），页面显示**本机时间**
- 点云与图像类大话题只统计流量，不解析内容
