# 二、网络架构（关键：桥接不可用，改用 NAT + 中继）

## 为什么桥接（Bridged）在这台机器上永久不可用

```
① 本机是 Secured-core PC 级别（固件强制 DMA 保护 / SMM Security Mitigations）
② Windows 11 24H2+ 的 VBS 由固件层面拉起，hypervisor 每次开机必启动
   实测关不掉的四个开关：
     内存完整性 HVCI = 0        → 无效
     WHP「虚拟机监控程序平台」= 禁用 → 无效
     VBS 主开关 EnableVirtualizationBasedSecurity = 0 → 无效
     bcdedit /set hypervisorlaunchtype off → 被 Windows 改回
   系统日志实锤：Microsoft-Windows-Hyper-V-Hypervisor Event ID 1「虚拟机监控程序已成功启动」
③ hypervisor 在跑 → VMware 只能退回 ULM 模式
④ ULM 下 vmnetbridge 桥接数据面【静默失效】
   实测：guest 带正确 IP 192.168.1.107/24，连宿主 192.168.1.109 都 ARP FAILED
```

另有**两个帮凶**（已卸载）：网易 MuMu 模拟器 `MuMuVMMDrv`、雷电9 `Ld9BoxSup`
—— 这两个 VirtualBox 系 hypervisor 驱动开机自启抢 VT-x。

## 实际采用的架构

```
┌─────────────────────┐        ┌────────────────────────────────┐
│  Windows 宿主        │        │  Ubuntu VM (op-icv)            │
│  以太网 192.168.1.109├───────►│  ens33 192.168.174.100/24      │
│  (内置 Realtek 1G)   │  NAT   │  网关 192.168.174.2 (VMnet8)   │
│                     │        │                                │
│  ROS 中继 (Node.js)  │◄───────┤  ROS_IP = 192.168.1.109        │
│  监听 192.168.1.109  │        │  (VM 对外宣称宿主地址)          │
│  :20000-20199        │        │                                │
└─────────┬───────────┘        └────────────────────────────────┘
          │ 网线（车载以太网转换板 → RJ45）
          ▼
┌──────────────────────────────────────────────────────────────┐
│  车机/域控 192.168.1.102  (Ubuntu 18.04, ROS Master:11311)    │
│  Jetson    192.168.1.103  (nvidia, 显控程序运行于此)           │
└──────────────────────────────────────────────────────────────┘
```

**原理**：
- **读方向**（VM 主动出站）：VMware NAT 转发时用**宿主自己的路由表**，宿主有直连路由 `192.168.1.0/24 → Realtek`，所以 guest 的包被宿主直接送到车机
- **写方向**（车机主动回连）：VM 的 ROS 节点对外宣称 `192.168.1.109`（宿主地址），宿主上跑 TCP 中继把 `192.168.1.109:20000-20199` 转发回 VM

## 中继运维

```
启动：双击  C:\Users\ASUS\Desktop\ROS-NAT-Relay\启动ROS中继.bat
自启：已放入 shell:startup（登录自动运行，窗口需保持打开）
```

> 中继不启动 → 车机无法回连 VM（订阅方向仍可用，但无法发布/控制）

# 四、⭐ 车辆受控的 4 个必要条件（缺一不可）

1. **网络通路** —— NAT + 宿主中继（本文第二节）
2. **显控正确启动** —— `./xiankong.sh`、图形终端、先 `cd ~/xk`（第三节）
3. **ROS_HOSTNAME 修正** —— `.19` → `.109`
4. **⭐ 车辆进入"自动巡航模式"：切 N 档 → 松手刹 → 按 AUTO**

> **第 4 条是"拖滑条没反应"的真正原因。** 它不在软件里（ROS 无相关服务、显控界面无此开关），
> 而是**车辆侧的物理操作**。软件只读取该状态（`Can_118` 的 `CruiseSwitchSts`）。

**CAN 侧证据**（操作前后对比）：

```
                        操作前                      操作后
Can_118 (巡航/EPB)   09 00/10 00 00 00 00 00 24 → 09 04/14 01 00 00 00 00 00
   byte1 bit2 置位 ← 【按 AUTO】巡航开关
   byte2 bit0 置位 ← 【松手刹】EPB 释放
Can_111 (档位)       00 03 00 00 00 00 11 00    → 00 03 00 00 C0 00 41 00
   byte4: 00→C0, byte6: 11→41 ← 【挂 N 档 + AUTO】
Can_208 (VCU 状态)   00 00 04 00 00 00 00 00    → 00 00 04 50 00 00 00 00
```

## 显控界面暴露的 4 个参数（`dynamic.cfg`）

| 参数 | 范围 | 含义 |
|---|---|---|
| `ICPV_Cmd_StrAngle` | 0~540 | 转向角（度） |
| `ICPV_Cmd_EPSDir` | 0~1 | EPS 转向方向 |
| `ICPV_Cmd_AccPelPosAct` | 0~100 | **油门执行器位置（= 驱动力）** |
| `ICPV_Cmd_BrkPelPosAct` | 0~30 | 刹车执行器位置 |

```yaml
ICPV_Cmd_StrAngle: 180.0          # 转向角
ICPV_Cmd_StrAngleLimit: 540.0     # 转向角上限
ICPV_Cmd_EPSXBW_En: 1             # EPS 线控使能
ICPV_Cmd_EPSDir: 0                # EPS 方向
ICPV_Cmd_StrAngleSpd: 150.0       # 转向角速度
ICPV_Cmd_Checksum: 0              # 校验和
ICPV_Cmd_RCnt: 0                  # 滚动计数器
ICPV_Cmd_TgtSft: 4                # 目标档位
ICPV_Cmd_AccPelEnable: 1          # 油门踏板使能
ICPV_Cmd_BrkPelEnable: 1          # 刹车踏板使能
ICPV_Cmd_AccPelPosAct: 0          # 油门执行器位置
ICPV_Cmd_AccPelPosActInv: 100.0   # 油门反向值 (100-x)
ICPV_Cmd_BrkPelPosAct: 0.0        # 刹车执行器位置
ICPV_Cmd_BrkPelPosActInv: 100.0   # 刹车反向值
ICPV_Cmd_BrkLightReq: 0           # 刹车灯请求
ICPV_Cmd_TgtSftEnable: 1          # 档位控制使能
ICPV_Cmd_ATOModeEnable: 1         # ATO 接管模式使能
IF_245: 1                         # 245 帧发送开关
IF_226: 0
```

## CAN 帧字节级解码（实测验证）

**xiankong 只发送两帧**：`226`（踏板执行器）+ `245`（转向/转向灯），各 100Hz（总线 tx ≈ 200 帧/秒）

```
ID 226  byte0 = ICPV_Cmd_AccPelPosAct      油门执行器位置     ✓ 实测 0x0F(15)/0x00
        byte1 = ICPV_Cmd_AccPelPosActInv   反向值 (100-x)    ✓ 实测 0x55(85)/0x64(100)
        byte2 = ICPV_Cmd_BrkPelPosAct      刹车执行器位置     ✓
        byte3 = ICPV_Cmd_BrkPelPosActInv   反向值            ✓
```

## 车辆状态帧（xiankong 读取）

| CAN ID | 字段 |
|---|---|
| `111` | GearLevPos（档位） |
| `118` | CruiseControlSts / CruiseSwitchSts / EPBSysVCU |
| `208` | AccPelPosFb / BrkPelPosFb / TgtSftFb / AccPelSta / BrkPelSta / ATOModFb / VCUSta |
| `1A3` | EPSDir / EPSMODE / StrAngle / StrAngleFb |
| `1A5` | StrAngleSpdDir / StrAngleSpd |
| `205` | YawRate / LongAcc |
| `212` | Forward Director |
| `23A` | ESCWhlRRSpd / RLSpd / FRSpd / FLSpd（四轮轮速） |
| `2AB` | DirIndicationRH / LH（转向灯） |
| `2CD` | 车门 / 车灯状态 |
| `32A` | VelSpd（车速，byte2-3 为 16 位大端） |
| `618` | BrkLgtSts（刹车灯） |
| `668` | BrkPed / AccPed |

**CAN 物理层**：`can0` 500kbps（bitrate 498701），总线负载约 2860 帧/秒

# 七、系统改动与恢复方法

## Windows 宿主

| 改动项 | 当前值 | 恢复方法（管理员） |
|---|---|---|
| 内存完整性 HVCI | 已关闭 | 设置 → Windows 安全中心 → 设备安全性 → 内核隔离 → 打开 |
| VBS 主开关 | `0` | `reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard" /v EnableVirtualizationBasedSecurity /t REG_DWORD /d 1 /f` |

| `bcdedit hypervisorlaunchtype` | `off` | `bcdedit /set hypervisorlaunchtype auto` |
| 已卸载 MuMu 模拟器（~8GB） | — | 重装即可（重装后 VMware 桥接仍不可用） |
| 已卸载雷电9（~33GB） | — | 同上 |

1. 向老师/整车厂索取 **CAN 报文矩阵（DBC）** —— 可完整解码所有状态帧
